# Demo 脚本

## 演示前检查

1. 后端已启动：`.\scripts\run_server.ps1`
2. 真机已连接并执行：`D:\Android\Sdk\platform-tools\adb.exe reverse tcp:8000 tcp:8000`
3. `.env` 中按需启用：`USE_CHROMA=true`、`USE_LLM=true`、`USE_ARK_EMBEDDING=true`
4. Android App 已安装到真机并能打开对话页。

## 最小闭环

1. 打开 Android App。
2. 输入：`推荐一款保湿眼霜，预算250以内`
3. 观察：AI 流式回复，并展示带主图的商品卡片。
4. 点击商品卡片，观察本地详情弹窗。
5. 在详情弹窗点击“打开链接”，跳转到 `/products/{product_id}` 本地商品详情页。

## 多轮与反选

1. 输入：`帮我推荐跑鞋`
2. 继续：`要轻量的`
3. 继续：`预算500以内`
4. 继续：`不要日系品牌`
5. 观察：筛选条件和排除条件逐步进入会话状态；如果严格匹配不足，系统应说明没有完全匹配，而不是返回无关商品。

## 上下文追问

1. 输入：`推荐一款保湿眼霜，预算250以内`
2. 继续：`第二个怎么样`
3. 观察：系统围绕上一轮第二个候选商品回答，并重新展示该商品卡片。
4. 继续：`再便宜点`
5. 观察：系统会基于上一轮候选价格自动收紧预算继续检索。

## 复杂约束回归

1. 输入：`推荐防晒霜，但我不要含酒精的，也不要日系品牌`
2. 观察：候选商品会执行多重排除；回答不得编造不存在的商品、价格、优惠或库存。

## 主动澄清

1. 输入：`推荐一款手机`
2. 观察：系统先追问拍照、续航、性能、性价比和预算，不直接返回商品卡片。
3. 继续：`拍照优先，预算4000`
4. 观察：下一轮查询会带上上一轮的“手机”主题。

## 商品对比

1. 输入：`科颜氏和AHC哪个眼霜更适合干皮`
2. 观察：系统返回对比型回答，并展示端侧对比面板和两侧候选商品卡片。
3. 可选输入：`小米和OPPO哪个拍照手机更适合预算4000`
4. 观察：对比时保留双方候选解释差异，但结论优先推荐预算内商品。

## 购物车闭环

1. 输入：`推荐一款保湿眼霜，预算250以内`
2. 继续：`把刚才那款加到购物车`
3. 观察：系统返回加购确认，并展示购物车面板。
4. 点击购物车面板中的商品行，观察详情弹窗。
5. 继续：`把数量改成2`
6. 观察：购物车总件数和总价实时更新。
7. 可选输入：`删除第一个` 或 `下单吧`
8. 观察：系统执行删除或模拟订单确认，不触发真实支付。

## 答辩说明点

- 最小闭环完整：客户端、后端、检索、流式、商品主图卡片、可点击详情页
- RAG 链路：JSON fallback 和 ChromaStore 都可用；Chroma 默认 hashing embedding，也可通过 `USE_ARK_EMBEDDING=true` 切换 Ark/Doubao embedding
- 模型链路：`USE_LLM=true` 时调用 Doubao/Ark，失败时自动回退模板回答
- 主动澄清：宽泛需求先补齐预算/偏好，再进入检索
- 上下文追问：支持“第二个怎么样”“再便宜点”等轻量多轮表达
- 商品对比：品牌/商品对会分侧检索，避免普通 Top-K 只召回一侧品牌
- 购物车：自然语言加购/删改数量，`cart_update` 实时刷新端侧状态
- 防幻觉：价格和商品信息来自 metadata
- 架构扩展：工具、输入处理器、后处理器、SSE 事件都可插拔
